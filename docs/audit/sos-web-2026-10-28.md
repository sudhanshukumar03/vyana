# Web SOS implementation 28 October 2026

Implemented saved SOS settings, separate doctor/report and emergency recipients, cancellable automatic countdowns, daily and sensor-quality reports, and a durable notification worker. Email uses Resend; optional SMS/voice use Twilio. The web page cannot activate the phone's built-in Emergency SOS. [Setup and behavior](../SOS.md) describes configuration and the prototype alert rules.

Automatic threshold monitoring uses fresh independent equipment snapshots from the active registered ESP32. Unavailable optical values, disconnected ECG leads, clipping, stale data and unverified sources do not independently initiate emergency calls. ECG rhythm classification is not implemented. Complete vital records contribute to reports without double-counting acquisition events. Raw ADC/clipping summaries are preserved when available.

Validation passed 74 API tests, 39 frontend tests and two new browser scenarios, with type checks, lint, production builds and source/reference checks. Browser scenarios cover saved consent/recipients, report queueing, cross-page countdown/cancellation, 320/1440 px layouts and automated accessibility. Provider adapters were mocked; no real messages or calls were sent. Database tests used only isolated disposable databases on port 55434. Screenshot evidence is under `artifacts/sos-2026-10-28/`.

The local development services were stopped when checked and were restarted through the existing development launcher. API readiness and migrated ECG-report fields were confirmed afterward. The app is available at http://localhost:5173. Actual email and phone delivery remain disabled because provider credentials have not been configured. No hardware upload or new physical sensor test was performed.
